# Raspberry Pi Pico W / Pico 2 W: управление светодиодом и вентилятором

Проект содержит код для **Raspberry Pi Pico W** и **Raspberry Pi Pico 2 W**, запускаемый на прошивке [MicroPython](https://micropython.org/). Контроллер подключается к Wi-Fi, поднимает небольшой HTTP-сервер и предоставляет веб-интерфейс и REST API для управления встроенным светодиодом, RGB-светодиодом , PWM-вентилятором и мотором. Светодиод также можно переключать физической кнопкой.

## Возможности

- подключение к Wi-Fi с автоматическими повторными попытками;
- веб-интерфейс без внешних библиотек и интернет-зависимостей;
- включение и выключение встроенного светодиода;
- переключение светодиода кнопкой между GPIO 16 и GND;
- вывод значений осей и кнопки аналогового джойстика в USB-консоль каждые 200 мс;
- независимое включение красного, зелёного и синего каналов RGB-светодиода;
- включение, выключение и регулировка скорости вентилятора;
- REST API для управления устройством.

## Подключение

Настройки по умолчанию:

| Устройство | Подключение |
| --- | --- |
| Кнопка | между `GPIO 16` и `GND`; используется внутренняя подтяжка к питанию |
| RGB: красный | `GPIO 20` |
| RGB: зелёный | `GPIO 19` |
| RGB: синий | `GPIO 18` |
| Вход 1 драйвера левого мотора | `GPIO 3`, PWM 20 кГц |
| Вход 2 драйвера левого мотора | `GPIO 4`, PWM 20 кГц |
| Вход 1 драйвера правого мотора | `GPIO 5`, PWM 20 кГц |
| Вход 2 драйвера правого мотора | `GPIO 6`, PWM 20 кГц |
| Вход `INA` драйвера вентилятора | `GPIO 1`, PWM 20 кГц |
| Вход `INB` драйвера вентилятора | `GPIO 2`, постоянный логический 0 |

Вентилятор нельзя питать непосредственно от GPIO. Используйте подходящий драйвер двигателя, питание согласно требованиям вентилятора и общую землю между Pico и драйвером.

У RGB-светодиода каналы подключены к GPIO со стороны «минуса», поэтому используется инверсная логика: уровень `1` на GPIO выключает цвет, уровень `0` — включает. После загрузки все три цвета выключены.

## Аналоговый джойстик

Подключайте при отключённом питании Pico. Схема для обычного пятиконтактного
модуля с двумя потенциометрами и кнопкой:

| Контакт джойстика | Контакт Pico | Физический номер вывода Pico |
| --- | --- | --- |
| GND | AGND | 33 |
| +5V | **3V3(OUT), 3,3 В** | 36 |
| VRX | GP26 / ADC0 | 31 |
| VRY | GP27 / ADC1 | 32 |
| SW | GP22, внутренняя подтяжка | 29 |

Надпись `+5V` на типовом пассивном модуле не требует питания именно от 5 В:
здесь питаем его от 3,3 В. **Не подключайте его к VBUS/5 В** при прямом
соединении VRX/VRY с Pico: входы АЦП рассчитаны на 0–3,3 В.
Если модуль содержит активную электронику и требует строго 5 В, эта схема
не подходит — сначала нужна документация на модуль и согласование уровней.
См. [документацию Pico](https://www.raspberrypi.com/documentation/microcontrollers/pico-series.html)
и [АЦП MicroPython](https://docs.micropython.org/en/latest/rp2/quickref.html#adc-analog-to-digital-conversion).

Модуль запускается вместе с проектом и печатает, например:

```text
[joystick] X=32768 Y=32912 SW=1
```

X/Y — сырые показания `read_u16()` от 0 до 65535; в центре обычно около
32768, возможны смещение и небольшой шум. SW=0 означает нажатие, SW=1 —
отпускание. Кнопка управления обрабатывается с подавлением дребезга 40 мс.
Пины и интервал вывода задаются в `config.py` (`JOYSTICK_*`).

Из каталога `/Users/odubinkin/Projects/pi-pico` запустите весь проект с
выводом в текущий терминал:

```bash
mpremote connect auto mount ./blink exec "import main"
```

Файлы читаются с компьютера через USB, поэтому терминал должен оставаться
открытым. Остановка — `Ctrl+C`. Джойстик опрашивается и без подключения к Wi-Fi.

## Подготовка Pico

1. Скачайте стабильную UF2-прошивку для своей платы:
   - [Raspberry Pi Pico W](https://micropython.org/download/RPI_PICO_W/);
   - [Raspberry Pi Pico 2 W](https://micropython.org/download/RPI_PICO2_W/).
2. Отключите Pico от USB, зажмите кнопку **BOOTSEL** и, не отпуская её, подключите плату к компьютеру.
3. Скопируйте UF2-файл на появившийся USB-диск `RPI-RP2`. После прошивки плата автоматически перезагрузится.
4. Установите на компьютер Python 3 и утилиту `mpremote`:

   ```bash
   python3 -m pip install --upgrade mpremote
   ```

5. Подключите Pico обычным USB-кабелем и проверьте, что плата обнаружена:

   ```bash
   mpremote connect list
   ```

Если подключено несколько MicroPython-устройств, добавляйте к следующим командам выбор порта, например `mpremote connect /dev/ttyACM0 ...` или `mpremote connect COM3 ...`.

## Настройка

Перед запуском откройте `config.py` и укажите как минимум имя и пароль сети Wi-Fi:

```python
WIFI_SSID = "имя-сети"
WIFI_PASSWORD = "пароль-сети"
```

При необходимости там же измените hostname, HTTP-порт, GPIO и параметры вентилятора. Не публикуйте `config.py` с настоящим паролем в открытом репозитории.

Pico W и Pico 2 W работают только с Wi-Fi 2,4 ГГц. Компьютер, с которого открывается веб-интерфейс, должен иметь доступ к той же локальной сети.

## Запуск с компьютера без копирования файлов на Pico

Этот режим удобен во время разработки: исходные файлы остаются на компьютере, а Pico читает их через USB. Соединение с `mpremote` должно оставаться открытым всё время работы программы.

Перейдите в каталог проекта и выполните:

```bash
mpremote mount . exec "import main"
```

`mpremote` подключит текущий каталог к файловой системе MicroPython как `/remote`, после чего код выполнится непосредственно на Pico. В терминале появится IP-адрес устройства. Для остановки нажмите `Ctrl+C`.

Если на самой плате уже установлен автоматически запускаемый `main.py`, сначала остановите его через REPL (`Ctrl+C`), либо временно переименуйте/удалите этот файл на Pico, чтобы он не мешал режиму разработки.

## Установка проекта на Pico

Из корня проекта скопируйте все Python-модули во внутреннюю файловую систему платы:

```bash
mpremote connect auto fs cp *.py :
```

Затем выполните перезагрузку:

```bash
mpremote connect auto reset
```

Файл `main.py` запускается MicroPython автоматически при включении или перезагрузке платы. После установки Pico может работать автономно: компьютер нужен только для питания по USB, если не используется другой подходящий источник питания.

Чтобы обновить проект, исправьте локальные файлы и повторите команду `mpremote cp`. Открыть только консоль устройства можно командой `mpremote repl`; выход из неё — `Ctrl+]` или `Ctrl+X`.

## Веб-интерфейс и API

После успешного подключения к Wi-Fi откройте выведенный в консоли адрес:

```text
http://<IP-адрес-Pico>/
```

Если локальная сеть поддерживает разрешение hostname/mDNS, также может работать адрес:

```text
http://maxpico.local/
```

Имя `maxpico` задаётся параметром `DEVICE_HOSTNAME` в `config.py`.

Доступные REST-маршруты:

| Метод и путь | Действие |
| --- | --- |
| `GET /api/blink/toggle` | Переключить встроенный светодиод. |
| `GET /api/rgb/status` | Получить состояния каналов RGB. |
| `GET /api/rgb/<red|green|blue>/toggle` | Переключить указанный канал RGB. |
| `GET /api/fan/toggle` | Включить или выключить вентилятор. |
| `GET /api/fan/status` | Получить состояние и выбранную скорость вентилятора. |
| `GET /api/fan/speed/<0-100>` | Установить скорость вентилятора по пользовательской шкале от 0 до 100%. |

Пример:

```bash
curl http://maxpico.local/api/fan/speed/50
```

Значение скорости `0%` в API не выключает вентилятор: оно соответствует минимальному рабочему PWM, заданному параметром `FAN_MIN_DUTY_PERCENT`. Для полного выключения используйте `/api/fan/toggle`.

## Моторы

Модуль `motor.py` включён по умолчанию (`MOTOR_ENABLED = True`). При загрузке
входы обоих драйверов удерживаются в 0, моторы не запускаются автоматически.
Веб-интерфейс содержит независимые панели «Левый» (GP3/GP4) и «Правый»
(GP5/GP6). Для каждого мотора доступны кнопки «Вперёд», «Стоп», «Назад» и ползунок скорости
0–100%. Изменение скорости не запускает остановленный мотор; 0% останавливает
его. Перед сменой направления нажмите «Стоп» и дождитесь остановки вала.

Ожидается двухвходовый драйвер с управлением PWM/0 для одного направления
и 0/PWM для другого; «Стоп» устанавливает 0/0. Мотор подключается к выходам
драйвера, питание мотора — к драйверу, земля Pico и драйвера должна быть общей.
Если у драйвера есть дополнительные EN/STBY/PWMA, они должны быть настроены
согласно его документации: этот модуль управляет только двумя входами направления каждого мотора.
При потере Wi-Fi мотор сохраняет последнюю команду.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/motor/<left|right>/status` | Состояние модуля, направление и скорость. |
| `GET /api/motor/<left|right>/forward` | Запуск вперёд с выбранной скоростью. |
| `GET /api/motor/<left|right>/reverse` | Запуск назад с выбранной скоростью. |
| `GET /api/motor/<left|right>/stop` | Остановить, сохранив выбранную скорость. |
| `GET /api/motor/<left|right>/speed/<0-100>` | Выбрать скорость; 0 останавливает мотор. |

Прямой реверс работающего мотора отклоняется с HTTP 400. Отключённый модуль
не занимает GPIO и возвращает HTTP 503 на команды, состояние доступно всегда.

Например, `/api/motor/right/forward` запускает правый мотор, а
`/api/motor/left/stop` останавливает только левый. Старые URL без `left/`
или `right/` сохранены для левого мотора. При завершении программы
останавливаются оба мотора. Оба используют одну частоту PWM 20 кГц.

## Управление моторами джойстиком

После запуска управление выключено и оба мотора остановлены. Нажатие SW
включает управление, следующее нажатие выключает его и останавливает оба
мотора. Удержание кнопки не вызывает повторных переключений. Если при
включении ручка отклонена, движение начинается сразу.

- Вперёд/назад (Y): оба мотора едут в выбранном направлении.
- Влево/вправо (X): разница скоростей; только боковое отклонение даёт разворот
  на месте (моторы вращаются в противоположных направлениях).
- Центр: остановка. Мёртвая зона каждой оси — 12%.
- Скорость команды 1–100 соответствует PWM 60–100%; нулевая команда выключает
  выходы. Это преобразование действует и для команд скорости из веб-интерфейса.
- Перед сменой направления каждого мотора выдерживается остановка минимум
  300 мс (`MOTOR_REVERSE_PAUSE_MS`). При необходимости увеличьте время под
  инерцию механизма; обратной связи о фактической остановке нет.

Опрос выполняется каждые 20 мс, вывод в консоль — каждые 200 мс. Если ось
работает наоборот, измените `JOYSTICK_INVERT_X` или `JOYSTICK_INVERT_Y` в
`config.py`. Левый мотор — GP3/GP4, правый — GP5/GP6.

Пока задача джойстика запущена, она задаёт состояние обоих моторов каждые
20 мс (включая остановку при выключенном управлении). Поэтому команды
движения из веб-интерфейса будут перезаписаны джойстиком.

Направление правого мотора инвертировано (`MOTOR_RIGHT_INVERT = True` в
`config.py`), чтобы учесть противоположную полярность установки. Инверсия
действует и для джойстика, и для веб-команд. Физические подключения GP5/GP6
остаются прежними.
